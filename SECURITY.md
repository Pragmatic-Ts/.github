# Security policy

Do not disclose vulnerabilities, credentials or private customer information in public issues or pull requests.

Use the affected repository's **Security → Advisories → Report a vulnerability** option if available. Private reporting is repository-specific and must be enabled by its maintainers; this file does not enable it.

If that option is absent, use an already-established private channel to the repository maintainer and request a secure reporting route before sending sensitive details. Do not assume an unpublished email address or public issue is a private channel. Maintainers must establish and document a working private reporting route before production release.

Provide a sanitized summary, affected version, impact and reproduction privately. Do not access other users' data or disrupt service to demonstrate a finding.

Supported versions and remediation commitments are defined by each product. This organization policy does not claim an SLA or support coverage that has not been established.

Maintainers should preserve evidence privately, assess impact, contain exposure, rotate compromised secrets, repair the issue, validate the fix and coordinate disclosure. Track an accountable incident owner and document follow-up controls without exposing sensitive details.
