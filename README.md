# Pragmatic-Ts Engineering Foundation

**Intelligent business infrastructure, built with product discipline.**

Pragmatic-Ts is a product-focused software engineering company. Our mission is to build reliable, scalable software that transforms inefficient business operations into intelligent digital systems.

We work across business SaaS, workflow automation, applied AI, developer infrastructure, and selective custom engineering. Our long-term strategy is globally competitive software products with recurring revenue. Client engineering can fund development and expose opportunities; it is not our ultimate business model.

This public repository contains company standards and reusable starting points. It contains no customer data, credentials, private product strategy or claims of completed product validation.

## What GitHub inherits

GitHub uses this public repository's supported community files and issue/PR templates as defaults where a repository has no corresponding local files. An existing local issue-template configuration overrides the organization issue templates as a group.

GitHub does **not** automatically copy or enforce AGENTS.md, company standards, product plans, CI workflows, branch rules, or licenses in product clones. Copy and adapt the product kit, adopt workflows explicitly, and configure rules on new repositories as described in the adoption guide. Existing product repositories are outside this setup's scope.

## Working model

Each product defines its own users, validated problem, scope, architecture, roadmap, and success criteria. No industry or technology stack is mandatory. Start with the simplest architecture that satisfies measured needs; add complexity only with evidence.

Use issues for actionable work, pull requests for review, ADRs for consequential decisions, and PROJECT.md for the current implementation ledger. A roadmap is an intent, not a promise. Production readiness requires executed evidence, not a completed checkbox alone.

## Maintaining this foundation

Changes use the pull request template and Foundation validation workflow. Pin action dependencies to verified commits and review update proposals. Preserve stable company principles; record exceptions with an owner, reason, compensating controls and review date.

Public availability is not a software license grant. Product owners must deliberately choose and add the appropriate license in each new repository; no default product license is imposed here.
